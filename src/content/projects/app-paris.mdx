  summary="A key part of the project was building an automated data collection pipeline. A Python script retrieves match information, scores, statuses, and upcoming fixtures from TheSportsDB API, then stores the data in PostgreSQL. The process runs automatically through Docker on a three-minute interval, keeping the local database regularly synchronized with the external source."
/>

<ArticleShortTextBlock
  title={{
    highlightTitle: 'A structured ',
    secondPartTitle: 'backend architecture',
  }}
  summary="The backend is built with FastAPI and SQLAlchemy, with PostgreSQL and TimescaleDB providing the data storage environment. Alembic handles database schema migrations, allowing changes to be versioned and applied in a controlled way. The REST API exposes endpoints to retrieve matches, submit bets, access betting history, and settle completed matches. Pydantic validates incoming data, while Scalar provides interactive API documentation for testing and exploring the available endpoints."
/>

<ArticleShortTextBlock
  title={{
    highlightTitle: 'Connecting ',
    secondPartTitle: 'data and interface',
  }}
  summary="The frontend is developed with Nuxt 3 and Vue.js. It communicates with the FastAPI backend to display match cards, collect predictions, and present the history of registered bets. Visual statuses distinguish ongoing matches from completed ones, while color-coded results make it easier to identify winning and losing bets. A dedicated action triggers the settlement process, retrieving final scores and updating the associated bet outcomes."
/>

<ArticleShortTextBlock
  title={{
    highlightTitle: 'Containerization ',
    secondPartTitle: 'and persistence',
  }}
  summary="Docker brings the application services together in a reproducible environment, simplifying setup and execution. Database migrations and persistent PostgreSQL storage ensure that the schema can evolve without relying on destructive table recreation, while recorded matches and bets remain available after services restart."
/>
